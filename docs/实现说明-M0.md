# 实现说明（M0 原型）

2026-11-13 交付。对应《三国读书内容网站-策划方案》的 P0 里程碑，全部产物在本仓库内。

## 1. 技术形态与方案差异

| 方案原定 | 实际实现 | 原因 |
|---|---|---|
| Vite + React + TS | 零依赖原生 ES Modules + hash 路由 | 起步不引工具链，`npm run serve` 即可预览；数据都是构建期生成，不需要框架运行时 |
| 内容 MD+YAML | 内容源 JSON（`content/*.json`） | 便于脚本校验；后续切 MD+YAML 只改构建脚本 |
| 数据库 | 无，构建期生成 `data/site.json` | 静态站直接 fetch JSON |
| 地图「真实经纬度切换」 | 砍掉，改「山水绘卷 + 年表」双视图 | 合规约束（见方案 9.4 / 逐帧拆解附录 C） |

## 2. 架构

```
content/catalog.json   120 回公版回目（来源 sanguo.5000yan.com）
content/master.json    导读 12 / 人物 65 / 关系 51 / 事件 9 / 史料 18
content/world.json     地名 22（仅示意坐标）/ 年表 38 / 时期 16 / 对问题 8
        │  scripts/build-content.mjs（构建期校验）
        ▼
data/site.json + data/search-index.json
        │  assets/js/app.js（hash 路由）→ pages.js（12 个页面）
        ▼
index.html  单壳页面，fetch JSON 后渲染
```

**构建期校验**（不过即退出码非 0）：人物关系两端必须存在、关系必须带 `sourceType ∈ {演义, 正史, 传说}`、导读引用回目必须存在、地名坐标只在示意范围内。

**出处三分法**进的是字段与统计口径，不是说明文字：`data/build-report.json` 里 `relationBySource: {正史 44, 演义 5, 传说 2}`，对应参考作品「正史 58 · 小说 159」的做法；典籍室按此分色（朱红/墨绿/棕金）。

## 3. 五个入口的实现要点

- **群英星图**（`star-map.js`）：Canvas 正交投影，人物按经纬度铺在球面，z 深度决定亮度与字号；匀速自转；点击人物缓动转到正面中心并放射关系线（按 sourceType 着色）；只标注正面可见的人名。65 人，非 DOM。
- **山河年表**（`scroll-map.js`）：纯 SVG 手绘山水（山、大河、大江、城池点），无任何底图；年份滑块联动事件点与时间轴；可叠加两人足迹线；地名古今对照仅在数据层，不采集位置数据。
- **对话台**（`pages.js` dialogue 段）：不接大模型。每个对话时期有 `year` 与知识边界，问题数据带 `answerByPeriod`；超出当年认知一律回「此事超出我此刻所知…」，回答卡可展开「依据 / 创作」。
- **故事馆**：120 回全部可筛（黄巾之乱/官渡/赤壁/三国鼎立/北伐/归晋 弧线），12 篇已校导读有完整内容，其余详情页明确显示「导读待校」占位而非空页。
- **赤壁专题**：`#/events/chibi`，按周瑜/曹操/诸葛亮/鲁肃四个立场切同一战役的叙述。
